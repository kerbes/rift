# Quickstart

## Prerequisites

- Go 1.21+
- Docker (running)
- k3d (`brew install k3d`)
- kubectl
- k9s (`brew install k9s`) — for TUI cluster browsing

## 1. Build

```bash
make build
```

## 2. Create k3d Clusters

This creates 3 local Kubernetes clusters, sets up service accounts with
bearer tokens, and generates the mock server topology and dev config.

```bash
make dev-clusters
```

Clusters created:

| Cluster       | API Port |
|---------------|----------|
| rift-dev      | 16443    |
| rift-staging  | 16444    |
| rift-prod     | 16445    |

Each cluster gets `app`, `monitoring`, and `logging` namespaces with a running
demo pod in each. The mock topology maps 3 EKS cluster names per account, but
all 3 point to the same underlying k3d cluster — so you'll see the same pods
regardless of which cluster name you pick within an account.

## 3. Start the Mock AWS Server

In a separate terminal:

```bash
make mock
```

This serves fake AWS SSO and EKS APIs on `localhost:8080` using the
topology generated by the k3d setup script. If port 8080 is already in
use, it will prompt you to restart.

Verify it's running:

```bash
curl -s http://localhost:8080/clusters
```

## 4. Run Rift Sync

```bash
make dev-sync
```

Expected output:

```
Discovered roles:    5
Discovered clusters: 45
Namespaces: tried=45 updated=45 errors=0
```

This writes AWS profiles to `~/.aws/config` and kube contexts to
`~/.kube/config` (all prefixed with `rift-`).

## 5. Launch the TUI

```bash
./rift ui
```

- Browse contexts with arrow keys
- Press `/` to filter
- Press `Enter` to select a context
- Press `k` to launch k9s — it should connect and show real namespaces

## 6. Run Tests

```bash
make test
```

## 7. Teardown

Stop the mock server (`Ctrl-C` or `make mock-stop`), then:

```bash
make dev-teardown
```

## One-Step Dev Setup

To run everything at once (build, clusters, mock server, sync, tests):

```bash
make dev
```

This starts the mock server in the background. Use `make mock-stop` to
stop it when done.
